# 檐雀单机 MVP

版本 0.1 · 2026-11-25 · 实现和验收待开始。

## 1. 完成定义

从公开仓库全新克隆，安装依赖后构建并打开游戏。玩家能从巢边出发，在街区内
行走、起飞、转向、滑翔、降落，收集并交付三片巢材。刷新页面后可以继续，筑巢
完成后仍可探索。公开试玩地址与对应源码提交一致。

## 2. 硬性内容范围

- 一只可辨识的原创低多边形麻雀，双翼、尾部与状态相匹配。
- 一片约 80 × 80 米街区，8 栋建筑、街道、庭院和树木。
- 至少 5 个可稳定停留的位置，3 片有稳定 ID 的巢材和 1 个巢。
- 键盘/鼠标控制、第三人称相机、拾取/交付提示和 0/3 到 3/3 的目标进度。
- 新游戏/继续、暂停、音量、重开确认、自动存档、异常存档恢复。
- 一套完成反馈、少量原创或授权明确的音效，以及可重复游玩的状态复位。

## 3. 连续可玩交付

| 里程碑 | 交付物 | 完成条件 |
| --- | --- | --- |
| M1 运动测试场 | 鸟、地面、墙面、坡顶、平台、固定模拟、跟随相机 | 行走起飞滑翔降落连续可玩；低帧率与失焦恢复不穿墙或失控 |
| M2 完整筑巢流程 | 正式街区、可见巢材、拾取携带交付、进度反馈 | 新玩家可在约 5–10 分钟的目标体验内完成三次交付，重复操作不刷进度 |
| M3 持续游玩与整理 | 自动存档、继续、完成后探索、音效与错误恢复 | 中途关闭重开保留一致进度，完成后能继续，重开正确复位 |
| M4 开源可玩发布 | 构建产物、真实试玩链接、完整 README、授权与版本记录 | 干净克隆通过安装构建，浏览器验收通过，公开链接与源码版本匹配 |

M2 的时长是设计目标，需要真实试玩确认。先完成 M1 的运动与相机手感，再扩大
正式街区。每个里程碑的任务、检查与剩余问题记录在实现计划中。

## 4. 验收矩阵

| 场景 | 预期结果 | 验收方式 |
| --- | --- | --- |
| 首次进入 | 加载完成后显示开始与操作提示，用户操作后进入游戏 | 浏览器 |
| 空间移动 | 起飞不顶入屋顶，转弯平滑，墙面接触有反馈 | 浏览器与物理用例 |
| 栖息与再起飞 | 选定屋檐能停稳，重新起飞正常，相机有清晰视野 | 浏览器 |
| 收集目标 | 只能在合法距离/落地状态拾取，一次携带一片 | 规则测试与浏览器 |
| 重复交付 | 同一片巢材只能推进一次，第三片触发完成 | 规则测试与浏览器 |
| 存档重开 | 已交付、携带与剩余物状态一致，从安全点继续 | 存档测试与浏览器 |
| 切换标签页 | 游戏与声音按暂停策略停止，恢复不保留旧按键 | 浏览器 |
| 存储异常 | 清楚提示当前无法保存，当前会话仍可游玩 | 存储故障用例与浏览器 |
| 异常恢复 | 坠出世界返回安全点，损坏存档经确认后恢复 | 用例与浏览器 |
| 重开 | 确认后进度、巢材和巢外观一起复位 | 规则测试与浏览器 |
| 完整筑巢 | 有完成反馈，继续探索和重新开始都可用 | 浏览器 |
| 发布 | 子路径资源正确加载，WASM 无 404，控制与保存生效 | 干净克隆构建和实际托管页面 |

## 5. 初始检查命令目标

第一轮代码初始化后提供 `npm ci`、`npm run dev`、`npm run build`、
`npm run test` 和 `npm run preview`。当前仓库为规划阶段，这些命令尚未实现。

发布前执行 focused tests、TypeScript 检查和 production build，再由作者完成上表的
浏览器验收。记录实际设备、浏览器、提交和未解决问题。只记录实际执行的检查。

## 6. 后续扩展

后续可考虑世界编辑、地图种子、天气、多种鸟、行动回放以及自主探索 Agent。
这些扩展在单机 MVP 验收后重新确定优先级。单机 MVP 的完成依据是上述连续玩法。
