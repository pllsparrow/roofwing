# 檐雀 Roofwing 产品需求

版本 0.1 · 2026-11-25 · 首轮实现依据。功能状态均为规划。

## 1. 定位与目标

一款桌面浏览器单机 3D 麻雀探索游戏。玩家用一只小鸟的视角穿过街巷，在屋檐
停留，寻找巢材，完成一次小小的筑巢旅程。目标体验是轻松、灵活、可重复游玩。

第一版让陌生玩家打开页面后理解操作，完成一次完整目标，退出后能够继续。
浏览器单机版通过验收后，再评估桌面客户端，复用已有游戏核心和资源。
GitHub 仓库提供独立安装、构建与修改的代码和素材来源说明。

## 2. 玩家与核心流程

面向喜欢低多边形场景、飞行探索和轻量休闲游戏的桌面玩家。

开始游戏 → 从巢边走出 → 起飞与滑翔 → 在屋顶降落 → 收集一份巢材 →
返回巢穴交付 → 完成三次交付 → 看见筑巢完成 → 继续探索或重新开始。

第一片巢材通过可见提示引导；后两片分布在不同高度或路径上。每次携带一片，
已交付的巢材即时反映到巢穴外观和进度。完成后保留探索能力。

## 3. 产品范围

| 能力 | 第一版行为 | 验收重点 |
| --- | --- | --- |
| 麻雀 | 低多边形身体、双翼与尾部；动作对应移动状态 | 飞行方向、振翅、落地和停留视觉一致 |
| 移动 | 行走、起飞、振翅爬升、滑翔下降、转向与降落 | 操作持续可控，帧率变化下速度稳定 |
| 相机 | 第三人称跟随，可旋转观察，自动避开建筑 | 视线连续、减少遮挡，恢复控制时无跳转 |
| 场景 | 一个约 80 × 80 米的街区，8 栋可识别建筑、街道、庭院、树木 | 至少 5 个可停留表面和 3 条能识别的探索路径 |
| 互动 | 接近巢材后按 E 拾取，回巢后按 E 交付 | 有距离、状态、容量判断；同一巢材仅交付一次 |
| 目标 | 收集并交付 3 片巢材 | 进度、携带物、完成反馈和实际状态一致 |
| 存档 | 自动保存已交付进度、携带物和最近安全栖息点 | 刷新后继续，异常数据有可恢复提示 |
| 菜单 | 开始、继续、暂停、音量、重新开始、操作说明 | 重开需确认，失焦自动暂停 |
| 反馈 | 振翅动画、轻量环境音、拾取/交付音效、完成反馈 | 静音有效，音频在用户操作后启动 |

后续候选包括更多街区、天气、可编辑地图、其他鸟类以及受控的自主探索 Agent。
其产品设计、实现与验收在单机核心版本之后单独决定。多人、账号与云存档留在后续范围。

## 4. 交互与美术方向

暖色石膏建筑、深蓝灰街道、粉橙树冠、柔和阴影和远景雾。通过轮廓、高度与色彩
区分区域，屋顶与巢材具备清楚的可见性。采用原创程序化几何搭建街区与麻雀。

HUD 只显示目标、交付进度、当前携带物、当前可用操作和必要错误信息。
按键说明在开始与暂停时可查看。状态提示不能只依赖颜色或声音。
桌面优先，提供键盘/鼠标操作。移动端适配在后续里程碑评估。

## 5. 发布质量

- 一次新游戏能够完整完成目标，并能在完成后继续探索。
- 支持正常退出、刷新、暂停、失焦与恢复。
- 存档不可用时允许继续游玩，同时明确当前进度无法保存。
- 遇到场景边界、掉出世界或不合理恢复位置时返回最近安全栖息点。
- 启动失败提供明确的重试与 WebGL 支持提示。
- 发布包包含本地构建需要的资源，素材授权和依赖说明可追溯。

性能目标、运行状态和错误恢复细则见 SPEC 与单机 MVP 文档。性能目标需在记录了
设备、浏览器、分辨率和提交版本的实测中确认。

## 6. 项目价值与证据

重点形成完整的游戏交付、运动/碰撞逻辑、相机体验、渲染优化与存档恢复能力。
通过真实代码、可玩版本、设计取舍、回归用例和可复现的性能记录呈现工程价值。
AI 辅助开发的使用方式可以如实记录。游戏中的自主 Agent 能力属于后续独立里程碑。
