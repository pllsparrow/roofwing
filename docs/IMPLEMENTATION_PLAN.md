# 技术选型与实现计划

2026-11-25 · 当前交付为独立公开仓库与设计文档。

## 1. 选型

| 领域 | 选择 | 理由与约束 |
| --- | --- | --- |
| 语言 | TypeScript strict | 显式状态、场景配置和存档合同，减少运行期状态错误 |
| 构建 | Vite | 快速本地开发和静态生产构建；固定版本与 lockfile |
| 3D | Three.js | 直接控制场景、材质、相机、实例化与资源生命周期 |
| 碰撞 | Rapier JavaScript/WASM | 复用形状查询与 kinematic 控制，自定义鸟的运动手感 |
| 界面 | 原生 DOM/CSS | 小型 HUD 与菜单，保持输入、模拟与渲染之间的清晰责任 |
| 存档 | localStorage | 小型版本化单人进度，覆盖拒绝写入、损坏和多标签页冲突 |
| 音效 | Web Audio | 原创轻量反馈音，受用户手势与静音设置控制 |
| 检查 | TypeScript + Vitest | 运动规则、状态机、互动与存档回归；浏览器验收另行执行 |
| 托管 | GitHub Pages | 静态应用分发，验证仓库子路径、WASM 资源和构建版本 |
| 许可证 | MIT | 原创代码与原创程序化素材采用 MIT；外部资产单独登记 |

这些是首轮实现的选定方案。首次安装依赖时查询相互兼容的当前版本，提交 lockfile。
Rapier 的 WASM 初始化、碰撞控制与构建资源路径是 M1 先验证的集成风险。
若控制器不适合飞行接触，先使用同一物理库的 shape cast 调整位移，再记录取舍。

## 2. M1 首轮实现任务

1. 初始化 Vite + TypeScript，提供 build/typecheck/test 命令、Node 版本约束和依赖锁。
2. 建立原生 DOM 入口与 Three.js/Rapier 启动、失败提示和资源销毁。
3. 在小型测试场搭建地面、墙、坡顶与平台，创建原创麻雀几何模型。
4. 接入输入映射和固定步长，连续实现行走、起飞、振翅、滑翔、降落、栖息。
5. 加入跟随相机、拖动观察、遮挡收缩与失焦暂停。
6. 用固定动作序列验证帧率变化和碰撞，再交付作者实际试玩手感。

M1 的交付是可操作的运动测试场。M2 在同一实现上加入街区与完整筑巢流程，
M3 完成持久化与失败恢复，M4 执行干净安装、托管和开源发布验收。

## 3. M2–M4 关键任务

- 场景配置同时驱动 Mesh、Collider、栖息点和互动对象，避免两套位置数据漂移。
- 拾取/交付动作先完成权威状态迁移，再更新视觉和保存请求。
- 测试存档版本、异常 ID、重复交付、重开与多标签页冲突。
- 首次合并资源前登记资产来源；程序化素材也记录作者和对应实现文件。
- GitHub Actions 在有代码后加入干净安装、类型检查、规则测试和构建。
- 发布工作流在本地构建与路径验证通过后配置 Pages，校验实际公开页面。
- README 以真实操作、截图、支持环境、技术取舍和实测结果更新；开发数据可复现。

## 4. 浏览器与客户端路线

当前先发布浏览器内运行的单机版，使用静态 Web 构建交付可玩链接。
作者于 2026-11-25 确认，单机版完成后再考虑桌面客户端。
客户端阶段评估 Windows/macOS、离线资源、版本更新、存档迁移与签名分发。
核心模拟和内容数据尽量复用，平台存储、输入、窗口与安装流程通过适配层接入。
具体客户端技术尚未选定。
